# Diffusion 接入验证记录

验证日期：2026-10-28。目标分支：`yuan_cx/inv_framework_indus_ct`。

## CPU 与接口

- 10 种方法的固定小模型对照：最终输出和调度器中间输出最大绝对误差均为 0。
- ReSample、DiffStateGrad 深分支：30 步主循环、实际 40 次调度器调用，覆盖像素域和潜空间优化；两边内部优化各限定 2 次。
- 统一示例的 12 个入口（10 种方法、mean-flow、LoRA）均通过。
- 完整 CPU 测试：44 passed、4 个 CUDA 项跳过；随后 4 个 NaSn CUDA 项独立通过。
- 新增的 GPU 时间步设备回归及内置随机调度器的 generator 回归单独通过；合计覆盖 45 个 CPU 项和 5 个 CUDA 项。

## 真实权重 GPU 对照

使用 PyTorch 2.7.0+cu118、Diffusers 0.32.2，关闭 TF32 和 cuDNN benchmark。
像素权重采用本地 LoDoChallenge UNet；潜空间权重采用官方 LoDoChallenge VQ/UNet，
固定 revision `03974e890f74c1e6d967d2709ded5a07ec226058`。
使用精确对角算子隔离网络/采样行为，4 步推理；DMPlug 为 1 步扩散、2 次优化。
这些是短流程数值对照，不是完整 CT 图像质量基准。

门槛仍为 rtol=1e-5、atol=1e-6，同时检查每次调度器输出。
原参考重复运行在部分方法上同样超过该门槛。VQ 的离散量化可放大微小输入变化；
这些证据说明存在原实现自身的 GPU 波动，尚不能把未通过项声明为严格数值等价。
未放宽门槛，也未把 CPU 一致性作为真实 GPU 一致性的替代。

同步辐射 768 权重的初次检查中，4 步 DMPlug 在原实现和迁移实现均显存不足；
后续采用较小权重和一步扩散完成 DMPlug 检查。完整多步优化的显存需求仍保留。

## NaSn 统一输入与评价

真实切片 1150、合成切片 991 各完成一次 mean-flow DDS 与 DDIM DDS 比较，
均只执行 2 个采样步、2 次 CG，验证尺度映射、几何、输出与指标链路。
DDIM 使用显式 2048 网格覆盖；合成验证中两者均显式指定 `(scale,offset)=(0.5,0.5)`，
这是连通性配置，不是对不同先验训练尺度的标定结论。
不将两步结果或不同训练数据的先验解释为算法优劣。
